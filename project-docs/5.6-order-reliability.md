# 5.6. Đảm bảo tính Tin cậy trong Vòng đời Đơn hàng (Order Reliability)

## (i) Đặt vấn đề
Đơn hàng "treo" (chọn vé nhưng không thanh toán) gây lãng phí tài nguyên kho. Mạng lag có thể khiến request gửi 2 lần.

## (ii) Giải pháp: Timeout Cleanup & Resumable Queue

### Chứng minh từ Codebase

**1. Booking Session Timeout (Cleanup Job):** `ticket-be/src/main/java/com/ticket/service/OrderCleanupJob.java`

```java
@Scheduled(fixedRate = 60000) // Chạy mỗi phút
@Transactional
public void cleanupExpiredOrders() {
    // Tìm các đơn hàng Confirmed (đã giữ vé) nhưng quá hạn thanh toán
    List<Order> expiredConfirmedOrders = orderRepository.findExpiredConfirmedOrders(now);
    
    for (Order order : expiredConfirmedOrders) {
        // Hoàn trả vé vào kho
        event.setAvailableTickets(currentTickets + returnedTickets);
        // Đánh dấu hết hạn
        order.setStatus(Order.OrderStatus.EXPIRED);
    }
}
```

**2. Resumable Queue (Redis State):** `ticket-be/src/main/java/com/ticket/service/OrderQueueService.java`

```java
// Lưu trạng thái request vào Redis để Client có thể resume khi reload trang
public void markAsProcessing(String requestId) {
    redisTemplate.opsForValue().set(key, QueueStatus.PROCESSING.name(), TTL, TimeUnit.MINUTES);
}

// Chống Duplicate Request (Idempotency)
public boolean markAsQueued(String requestId) {
    // Chỉ cho phép nếu Key chưa tồn tại (SETNX)
    return redisTemplate.opsForValue().setIfAbsent(key, QueueStatus.QUEUED.name(), ...);
}
```

## (iii) Kết quả
Loại bỏ hoàn toàn vé ảo, tối ưu hóa doanh thu. Đảm bảo trải nghiệm người dùng liền mạch (Reload trang không mất trạng thái đặt vé).
