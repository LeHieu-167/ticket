# 5.3. Phản hồi trạng thái thời gian thực (Real-time Feedback)

## (i) Đặt vấn đề
Với kiến trúc bất đồng bộ (Kafka), người dùng không biết ngay kết quả đặt vé (Thành công/Thất bại). Polling liên tục (F5) gây lãng phí tài nguyên.

## (ii) Giải pháp: WebSocket (STOMP) + In-Memory Broker
Sử dụng WebSocket để server chủ động đẩy thông báo kết quả xuống client ngay khi xử lý xong.

### Chứng minh từ Codebase

**1. Cấu hình WebSocket:** `ticket-be/src/main/java/com/ticket/config/WebSocketConfig.java`

```java
@Override
public void configureMessageBroker(MessageBrokerRegistry config) {
    // Kích hoạt In-Memory Broker
    config.enableSimpleBroker("/topic", "/queue");
    config.setUserDestinationPrefix("/user");
}

@Override
public void registerStompEndpoints(StompEndpointRegistry registry) {
    // Endpoint có hỗ trợ SockJS fallback
    registry.addEndpoint("/ws").setAllowedOriginPatterns("*").withSockJS();
}
```

**2. Gửi thông báo (Service):** `ticket-be/src/main/java/com/ticket/service/NotificationService.java`

```java
public void sendToUser(UUID userId, NotificationMessage notification) {
    // Đẩy tin nhắn trực tiếp xuống user cụ thể qua WebSocket
    messagingTemplate.convertAndSendToUser(
            userId.toString(), 
            "/queue/notifications", 
            notification
    );
}
```

**3. Tích hợp trong luồng xử lý đơn:** `ticket-be/src/main/java/com/ticket/service/OrderConsumerService.java`

```java
// Sau khi xử lý xong đơn hàng (Success hoặc Failed)
notificationService.notifyOrderProcessed(
    customerId, 
    order.getId(), 
    "CONFIRMED", 
    successMessage
);
```

## (iii) Kết quả
User nhận được phản hồi tức thì (< 100ms) sau khi hệ thống xử lý xong. Loại bỏ hoàn toàn việc polling, tiết kiệm băng thông và tài nguyên server.
