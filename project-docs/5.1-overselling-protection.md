# 5.1. Xử lý đồng thời và chống bán vượt số lượng (Overselling)

## (i) Đặt vấn đề
Trong các đợt Flash Sale, hàng nghìn yêu cầu cùng truy cập vào cơ sở dữ liệu để mua một số lượng vé giới hạn. Nếu chỉ kiểm tra tồn kho bằng Database query thông thường, khoảng thời gian trễ giữa lúc "Đọc tồn kho" và "Cập nhật tồn kho" sẽ gây ra Race Condition, dẫn đến bán vượt số lượng (Overselling).

## (ii) Giải pháp: Distributed Lock với Redisson
Hệ thống sử dụng **Redis Distributed Lock** (qua thư viện Redisson) để tuần tự hóa các yêu cầu mua vé cho cùng một sự kiện.

### Chứng minh từ Codebase

**File:** `ticket-be/src/main/java/com/ticket/service/OrderConsumerService.java`

```java
// 1. Tạo khóa phân tán dựa trên Event ID
String lockKey = "event:lock:" + orderRequest.getEventId();
RLock lock = redissonClient.getLock(lockKey);

try {
    // 2. Cố gắng lấy lock với thời gian chờ 10s, giữ lock tối đa 30s
    // Chỉ 1 thread được vào Critical Section tại 1 thời điểm
    boolean isLocked = lock.tryLock(LOCK_WAIT_TIME, LOCK_LEASE_TIME, TimeUnit.SECONDS);

    if (isLocked) {
        try {
            // 3. Xử lý logic nghiệp vụ trong vùng an toàn
            processOrder(orderRequest);
        } finally {
            // 4. Luôn giải phóng lock để tránh Deadlock
            lock.unlock();
        }
    } else {
        // Xử lý khi không lấy được lock (Retry hoặc Queue lại)
        createPendingOrder(orderRequest, "Không thể lấy lock - Đang chờ xử lý");
    }
}
```

**File:** `ticket-be/src/main/java/com/ticket/service/OrderConsumerService.java` (Logic trừ kho)

```java
// Logic này được bảo vệ bởi Lock ở trên
@Transactional
protected void processOrder(OrderRequest orderRequest) {
    // ...
    // Kiểm tra tồn kho
    if (availableTickets < requestedQuantity) {
        createFailedOrder(orderRequest, "Không đủ vé.");
        return;
    }

    // Trừ kho an toàn
    Integer newAvailableTickets = availableTickets - requestedQuantity;
    event.setAvailableTickets(newAvailableTickets);
    eventRepository.save(event);
    // ...
}
```

## (iii) Kết quả
Đảm bảo tính toàn vẹn dữ liệu tuyệt đối (Data Integrity). Không bao giờ xảy ra trường hợp số vé bán ra lớn hơn số vé thực tế trong kho, ngay cả khi có hàng nghìn request đồng thời.
