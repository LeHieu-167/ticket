# 5.2. Chịu tải đột biến với kiến trúc hướng sự kiện (Event-Driven)

## (i) Đặt vấn đề
Xử lý đồng bộ (Synchronous) khiến server dễ bị quá tải (Thread Pool Exhaustion) khi lượng truy cập tăng đột biến. Database trở thành nút thắt cổ chai khi phải gánh hàng nghìn transaction cùng lúc.

## (ii) Giải pháp: Apache Kafka
Hệ thống chuyển sang xử lý bất đồng bộ. Request được đẩy vào Kafka và trả về kết quả "Đang xử lý" ngay lập tức cho người dùng.

### Chứng minh từ Codebase

**1. Producer (Gửi Message):** `ticket-be/src/main/java/com/ticket/service/OrderProducerService.java`

```java
public CompletableFuture<SendResult<String, OrderRequest>> sendOrderRequest(OrderRequest orderRequest) {
    // Sử dụng Event ID làm Partition Key để đảm bảo thứ tự xử lý cho cùng 1 sự kiện
    String key = "event-" + orderRequest.getEventId();

    // Gửi message vào Topic bất đồng bộ
    return kafkaTemplate.send(orderRequestsTopic, key, orderRequest);
}
```

**2. Consumer (Xử lý Message):** `ticket-be/src/main/java/com/ticket/service/OrderConsumerService.java`

```java
@KafkaListener(
        topics = "${kafka.topic.order-requests}",
        groupId = "${spring.kafka.consumer.group-id}",
        containerFactory = "kafkaListenerContainerFactory"
)
public void consumeOrderRequest(OrderRequest orderRequest) {
    // Consumer tự động kéo message về để xử lý
    // Tốc độ xử lý phụ thuộc vào khả năng của Database, không làm sập server
    processOrder(orderRequest);
}
```

**3. Cấu hình Kafka:** `ticket-be/src/main/java/com/ticket/config/KafkaConfig.java`

```java
@Bean
public NewTopic orderRequestsTopic() {
    return TopicBuilder.name(orderRequestsTopic)
            .partitions(3)  // Phân chia thành 3 luồng xử lý song song
            .replicas(1)
            .build();
}
```

## (iii) Kết quả
Hệ thống có thể tiếp nhận hàng nghìn request/giây mà không bị sập (High Availability). Trải nghiệm người dùng mượt mà hơn do không phải chờ đợi phản hồi từ Database.
