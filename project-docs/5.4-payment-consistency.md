# 5.4. Đảm bảo tính nhất quán trong thanh toán (Payment Consistency)

## (i) Đặt vấn đề
Giao dịch thanh toán online dễ gặp lỗi do mạng (timeout, duplicate callback). Cần đảm bảo trừ tiền thì phải có vé, và không xử lý 2 lần cho 1 giao dịch.

## (ii) Giải pháp: State Machine + Idempotency + Checksum
Sử dụng HMAC-SHA512 để xác thực toàn vẹn dữ liệu và kiểm tra trạng thái đơn hàng để đảm bảo tính lũy đẳng (Idempotency).

### Chứng minh từ Codebase

**File:** `ticket-be/src/main/java/com/ticket/service/VNPayService.java`

**1. Xác thực chữ ký số (Integrity):**
```java
// Hash dữ liệu nhận được
String calculatedHash = VNPayUtil.hmacSHA512(vnPayConfig.getVnpSecretKey(), signValue);

// So sánh với chữ ký từ VNPay
if (!calculatedHash.equalsIgnoreCase(vnpSecureHash)) {
    log.warn("⚠️ VNPay signature mismatch...");
    // Xử lý cảnh báo hoặc từ chối
}
```

**2. Kiểm tra trạng thái & Lũy đẳng (Idempotency):**
```java
// Kiểm tra đơn hàng đã được xử lý chưa (Idempotency Check)
if (order.getPaymentStatus() == Order.PaymentStatus.PAID) {
    return new PaymentResponse("02", "Đơn hàng đã được thanh toán", null);
}

// Transactional: Cập nhật trạng thái + Tạo vé cùng lúc
@Transactional
public boolean handlePaymentCallback(Map<String, String> vnpParams) {
    // ... verify hash ...
    if ("00".equals(vnpResponseCode)) {
        order.setPaymentStatus(Order.PaymentStatus.PAID);
        // Tạo vé ngay trong transaction
        ticketService.generateTicketsForOrder(order.getId());
    }
}
```

## (iii) Kết quả
Đảm bảo tính nhất quán tuyệt đối (Consistency). Không bao giờ bị mất vé khi đã trừ tiền, và không bao giờ xuất vé 2 lần cho 1 lần thanh toán.
